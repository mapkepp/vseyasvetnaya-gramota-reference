# Восстановление и продвижение main

## Каноническая схема

- `main` — опубликованная стабильная линия. До успешной проверки кандидата не изменяется.
- `dev` — рабочая линия автономного развития.
- `archive/main-pre-rebuild-20260926` — сохранённый снимок main перед текущей попыткой перестройки.
- `archive/dev-pre-rebuild-20260926` — сохранённый снимок dev.
- `rebuild/main-candidate-20260926` — изолированный кандидат, в котором проверяется объединение main + dev.

## Правило

Нельзя заменять main простым копированием dev и нельзя удалять старую историю ради «чистоты».

Цикл:

1. сохранить снимки;
2. собрать кандидата из main + dev;
3. при конфликте остановиться и записать конфликт;
4. при чистом объединении выполнить проверки;
5. только после успешных проверок разрешить продвижение кандидата;
6. после продвижения сохранить предыдущий main как точку мгновенного возврата;
7. ошибки не откатывают прогресс dev — они блокируют публикацию, пока проблема не исправлена.

## Автоматическое восстановление

`.github/workflows/rebuild-main-candidate.yml` периодически пересобирает кандидата. При конфликте или ошибке main не меняется. Состояние записывается в `data/research/release-readiness.json`.

Это соответствует fail-closed подходу: автоматизация может чинить и проверять только безопасно определённые состояния, а неоднозначное объединение не выполняется вслепую.

## Возврат

Возврат должен выполняться переводом защищённой линии на последний проверенный снимок, а не удалением истории. Архивные ветки сохраняются отдельно и не считаются мусором.
