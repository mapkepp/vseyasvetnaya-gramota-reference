# ВсеЯСветная Грамота — Буковник 147

Исследовательский справочник по заявляемой системе «ВсеЯСветной Грамоты».

## Что является источником истины

`data/bukovy.json` — канонический каталог проекта. Сейчас в нём **68 подтверждённых опубликованных карточек с изображением/описанием**. Источник заявляет 147 Буков; оставшиеся **79 позиций не заполняются догадками** и ведутся отдельно в контуре восстановления.

## Архитектура

Главная единица интерфейса и API — **Букова**.

- `data/bukovy.json` — источник истины.
- `api/v1/bukovy-summary.json` — быстрый каталог для клиентов.
- `api/v1/bukovy-profiles.json` — полный bulk API.
- `api/v1/bukovy/{entry_id}.json` — профиль одной Буковы.
- `api/v1/bukovy-manifest.json` — стабильный список профилей.
- `api/v1/recovery.json` — исследовательское состояние восстановления 147-позиционного массива; кандидаты не являются каноническими позициями.
- `api/v1/recovery.schema.json` — схема recovery API.
- `data/practice/*` — практические записи и истории.
- `index.html` — клиент API; подробные блоки загружаются по требованию.

Истории практиков — ключевой исследовательский слой проекта: для каждой истории в первую очередь фиксируются **действие**, затем **сообщённый результат**, условия применения, уровень свидетельства и источник. Повторяющиеся действия/результаты можно сравнивать только там, где источник позволяет связать их с конкретной Буковой или составным ставом. Практические записи и истории не являются независимым подтверждением эффективности.

## Статусы и доказательность

- `local-copy` — исходное опубликованное изображение сохранено локально.
- `external-or-missing` — локальной копии изображения пока нет; сейчас это относится к **Фите**.
- `candidate` / `secondary-description` — вторичное свидетельство для восстановления; не является канонической записью.
- Практические и эзотерические эффекты приводятся как **утверждения источников/свидетельства**, а не как установленные научные факты.

## Проверки

`scripts/validate-bukovy.py` проверяет IDs, порядок и количество карточек, source-image numbers, coverage, API-синхронизацию, профили, manifest и быстрый summary.

GitHub Actions автоматически пересобирает производный API, фиксирует его в `main`, запускает валидацию и публикует GitHub Pages одним конвейером. Это устраняет рассинхронизацию canonical data ↔ API и лишние отдельные workflow-запуски.
