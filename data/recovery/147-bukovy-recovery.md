# Восстановление 147 Буков — рабочий контур

Статус: **исследование, не канонический каталог**.

## Что установлено

1. Основной веб-источник заявляет 147 Буков для Земного Плана Восприятия и 1234 Буковы для Вселенского. Это **утверждение самого источника**, а не независимая историко-лингвистическая верификация.
2. В репозитории из этого источника уже зафиксированы 68 карточек, каждая привязана к опубликованному GIF Image7.gif–Image74.gif.
3. Последовательность 68 карточек подтверждается несколькими независимыми копиями публикации; в частности LiveInternet воспроизводит начало последовательности и группы «И», а другие копии воспроизводят полный текст описаний.
4. Найденный текст, связанный с изданием/учебником 2009 года, прямо говорит о 147-буковой азбуке и отдельно описывает дополнительные графические формы и группы. В нём, например, говорится о десяти вариантах группы «И» в 147-буковой азбуке; это показывает, что число 147 нельзя получать простым дополнением текущих 68 карточек до обычного русского алфавита.
5. Поэтому **79 незаполненных позиций пока не являются 79 известными именами**. Они должны восстанавливаться из факсимиле/сканов и сопоставления графем, а не из догадки по названию.

## Текущая каноническая граница

Канонический data/bukovy.json содержит только карточки, для которых найдено опубликованное описание с привязанным изображением. Непроверенные кандидаты туда не добавляются.

## Следующий этап

1. Составить машинно-проверяемую карту страниц/фрагментов издания 2009 года.
2. Выделить из неё все места, где названа или графически обозначена отдельная Букова.
3. Для каждой найденной формы сохранить: исходное написание; нормализованное имя, если оно однозначно; номер страницы/фрагмента; источник; наличие изображения; связь с уже известной карточкой, если она доказуема.
4. Только после этого расширять канонический каталог и пересчитывать coverage.
5. Для каждой добавленной позиции сохранять provenance так, чтобы API мог отличать source-described, facsimile-only, candidate и unresolved.

## Жёсткое правило

Нельзя считать название доказанным названием отдельной Буковы только потому, что оно встречается в свободном тексте. Графема, имя и описание должны быть связаны источником или помечены как неопределённые.

## Candidate-count semantics

В реестре сейчас больше кандидатных имён, чем 79 незаполненных canonical-позиций. Это нормально: кандидаты включают варианты написания, составные формы и вторичные упоминания и **не являются нумерованными слотами 1:1**. Поле `canonical_unfilled_count` в recovery API остаётся единственным счётчиком незаполненных заявленных позиций.
