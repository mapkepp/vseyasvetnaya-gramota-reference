# Журнал запусков

Единица хранения — **run** (один запуск процесса), а не строка интерфейса.

## Архитектура

- `data/research/run-history/YYYY/MM/DD/<branch>.json` — дневные партиции по ветке.
- `run_id` — устойчивый уникальный ключ; повторное наблюдение обновляет ту же запись, а не создаёт дубль.
- Время внутри журнала всегда UTC ISO-8601.
- Интерфейс переводит время в выбранный пользователем пояс (по умолчанию UTC+3).
- Поля отображения отделены от фактов: процесс, статус, длительность, старт, завершение, ветка, идентификатор запуска.
- Для исследований отдельный журнал `research-history.json` остаётся дочерним источником деталей задач/свидетельств.
- GitHub API используется как live/fallback-источник, если постоянная партиция ещё не опубликована.

Такой формат не разрастается одним гигантским JSON и позволяет странице загружать только нужные ветки и даты. Модель можно без изменения смысла перенести в SQLite/PostgreSQL/IndexedDB.
